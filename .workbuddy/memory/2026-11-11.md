## autumn-data-meta-jdbc：MetaMapper 返回动态生成的 MetaClass（已提交）
- 需求：门面层直接返回 `MetaClass` 而不是 `MetaRow`；`MetaClass` 本身要用 FreeMarker 动态生成；
  定位在「完全静态（运行期建表做不到 / 要反射）」与「完全动态（Map 没类型）」之间。
  用户强调：MetaClass 必须知道每个字段类型，后续处理才稳妥。
- 实现：common 的 `MetaClass` 补公共契约（`get/set/property` + 类型化 getter + `toMap/toJson`），
  新增 `MetaValueReader`；meta-jdbc 新增 `MetaEntityTemplate`（FreeMarker `meta-class.ftl`）、
  `MetaEntityCompiler`（javac + URLClassLoader）、`MetaEntityRegistry`（结构指纹缓存）、
  `MetaEntityReader` / `MetaEntityColumns` / `MetaEntityModel`；生成类是 `MetaClass` 子类，
  有真实类型字段/getter，逐行映射零反射；`MetaRow` 删除，测试示例与上层示例同步改为 `MetaClass`。
- 决策：指纹进包名，refresh 生成新类、旧实例不失效；源码可配置落盘（可固化成静态类）；
  引擎级共享 registry，同构表只编译一次；运行期需要完整 JDK。
- 验证：`mvn -B test` 全 reactor 7 模块全绿（meta-jdbc 22 个用例，using 63 个）。
- 其他：README / docs/meta-dynamic-crud.md 同步；starter 新增 `entity-source-directory` 配置。
- 用户说明：既有实现是豆包/qwen 做的，很多地方不满意，上层 API 后续还要调整 —— 这次只动底层与门面。

## autumn-data-meta-jdbc：三处按表缓存改为有界 LRU（本次，尚未提交）
- 起因：用户要把 `MetaTableRegistry` 的 `ConcurrentHashMap` 换成「Spring Boot 推荐的 Caffeine Cache」，
  默认缓存 10_000 张表；随后给出替代方案「或基于 CHM 自写 LRU、不加依赖」，
  经确认选 **自研零依赖 + 三处一起收口**；并追加要求：**缓存上层 API 要参考 Caffeine，方便未来切换**。
- 核实：Spring Boot 4.1.2 官方文档中，无任何缓存库时默认其实是 `ConcurrentMapCacheManager`（Simple，
  原文说不建议生产用）；Caffeine 是官方支持的生产级本地缓存、classpath 存在即自动配置
  `CaffeineCacheManager`，并取代 Guava Cache。本项目核心层零 Spring 依赖，若用 Caffeine 也只能用
  原生 `Cache` API，不能用 Spring Cache 抽象。BOM 已管 3.2.4、本地 jar 已在。
- 实现：新增 `BoundedCache`（接口，方法名/语义对齐 Caffeine `Cache`：getIfPresent / get(key,fn) /
  put / invalidate / invalidateAll / estimatedSize / cleanUp，扩展 invalidateIf / maximumSize）、
  `LruCache`（LinkedHashMap accessOrder + ReentrantLock 保护顺序与淘汰；加载在锁外 + pending 表
  做同 key 单飞；淘汰同步，size 恒不超上限）、`BoundedCaches`（工厂，未来换 Caffeine 只改这一行）。
- 接入：`MetaTableRegistry` / `MetaEntityRegistry` / `MetaStatementStore` 三处统一上限；
  `MetaMapperOptions` 加 `tableCacheSize`（默认 10_000，保留原有 5/6 参兼容构造），
  starter 加 `autumn.data.meta.mapper.table-cache-size`，`MetaMapperEngine.createClient` 贯通。
  注意：手工 `register(MetaTable)` 单独存 `overrides`、**不参与 LRU 淘汰**（避免业务覆盖被静默丢弃），
  但 `refresh(table)` 仍按原语义清掉它。
- 决策：淘汰后重新生成实体类是「同名类 + 新 ClassLoader」，互不冲突；Mapper XML 文件归使用方所有，
  淘汰后只重读不重写。
- 验证：`mvn -B test` 全 reactor 7 模块 BUILD SUCCESS；meta-jdbc 35 个（新增 `BoundedCacheTest` 9 个
  + `MetaMapperDynamicTest` 26 个），using 63 个。README / docs/meta-dynamic-crud.md 同步。
