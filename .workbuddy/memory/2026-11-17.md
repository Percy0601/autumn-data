# 2026-11-17

## new feature: metaFind / metaSave / metaUpdate / metaDelete（按「数据源 + 命名空间」放语句）

用户给了用法、要求我写实现（`TODO` 里的两行调用就是验收标准）：

```java
MetaMapper.metaFind(TABLE, MetaQuery.all());
MetaMapper.metaFind(datasource, namespace, tablename, queryId, queryParam);
```

- **新增** `sql/MetaSqlFileStore`：寻址 `meta/{datasource}/{namespace}/{table}.xml`
  （classpath `meta/`；系统属性 `autumn.data.meta.sql.root` 可指到磁盘做开发热改）。
  懒加载（构造不扫目录）、有界 LRU、按「mtime+size」判过期自动重读、宽松解析
  （没有 `<mapper>` 根 / 根上漏 namespace 都能用，解析前补壳）。与旧 `MetaStatementStore`
  （`<meta-directory>/mapper/<表名>.xml`，只有表名一个寻址键）并列存在，互不替代。
- **`MetaMapperClient`** 新增构造重载（第 10 个参数传 store，旧 9 参构造保留）、
  `metaFind(2/3 参)/metaSave/metaUpdate/metaDelete` + 5 参完整形态 + `metaStatementIds` /
  `clearMetaSqlCache` / `metaSqlStore()`；`clearAllCaches()` 现在也清语句库，`cacheStats()` 多两项。
- **回退规则**（关键设计）：`metaFind/metaSave/metaUpdate` 文件里没语句就退回 `MetaSqlBuilder` 现拼
  （等价 `findList/save/update`），所以「先上线后补语句」可用；`metaDelete` 不生成物理删除——
  只有文件里写了 `<delete id="metaDelete">`（或写成 `<update>` 的逻辑删除）才执行，否则退化为
  `MetaSqlBuilder.logicDelete(...)`（配置了逻辑删除列时），两者都无则报错。
- **`MetaQuery` 怎么和文件里的 SQL 共存**：文件里的 `metaFind` 当「基础语句」（不依赖外部参数），
  调用方的条件/排序包成派生表叠在最外层 `SELECT * FROM (<base>) autumn_meta_base WHERE ...`；
  无条件下直接用原文。不做文本手术（`<if>/<foreach>` 展开后没有可靠切点）。
  为此 `MetaSqlBuilder` 拆出 `appendConditions(..., logicDeleteFilter)`，新增 `where(table, query)`（不补逻辑删除）
  与 `logicDelete(table, entity)`。槽位顺序坑：`SET ? WHERE ?`，binds 必须 SET 在前。
- 静态门面常量：`MetaMapper.DEFAULT_NAMESPACE/META_FIND/META_SAVE/META_UPDATE/META_DELETE`；
  完整形态用 `engine().client(datasource)` 路由，所以池名 == 目录名。
- 测试：`sql/MetaSqlFileStoreTest`（8）+ `engine/MetaMapperMetaApiTest`（10，含 classpath
  `src/test/resources/meta/default/default/form_order.xml` 走静态门面）；全 reactor `mvn -o test` 绿。
- 文档：README 新增小节 + 修掉「没有 delete」那条；`docs/meta-dynamic-crud.md` 加同主题小节与「谁读文件」表格行。
