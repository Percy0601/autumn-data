## 新增 AutumnDataContextHolder + 大页关联分级加载

### 新增运行期类（`autumn-data-jdbc/runtime`，零 Spring 依赖）
- `AutumnDataContext`（record）：`largePageAssociationEnabled`（默认 true）+ `largePageThreshold`（默认 20），不可变 → 与 `InheritableThreadLocal` 配合安全。
- `AutumnDataContextHolder`：用 `InheritableThreadLocal` 支持 `new Thread()` 子线程继承；提供 `wrap(Runnable)`/`wrap(Callable)` 做**线程池透传**（提交时捕获、worker 执行前还原、执行后还原为原值/清除）；`get()` 惰性建默认，`set/clear` 由调用方控制。

### 生成代码改动（`autumn-data-jdbc-compiler/ImplementationSource`）
- `findAllPageableBody` 仅对分页生效：页大小 `pageable.size() <= __ctx.largePageThreshold()`（默认 20）→ 一律 eager 加载 1:n/n:1；超过阈值改由 `AutumnDataContextHolder.get().largePageAssociationEnabled()` 决定（关则跳过关联装配，省去大页额外查询）。非分页 `findAll`/`findById`/派生查询不受影响。
- 文案：新增 `CONTEXT_HOLDER`/`AUTUMN_DATA_CONTEXT` 两个 FQN 常量。

- `docs/spring-data-derived-query.md` 第 8 节补第 5 点「大页关联加载优化（AutumnDataContextHolder）」。
- `GeneratedUserRepositoryImplTest` 加两例：`largePageSkipsAssociationLoadingWhenContextDisabled`、`smallPageAlwaysLoadsAssociationsRegardlessOfContext`。

##  refinement：AutumnDataContextHolder 改为 PageHelper 式一次性上下文
- 痛点：原 `set(...)` + 手动 `clear()` 太繁琐。
- 改为双 ThreadLocal：`CONTEXT`（持久，继承式）+ `PENDING`（一次性，继承式）。`get()` 优先 PENDING→CONTEXT→默认。
- 新增 `startContext(ctx)` / `disableLargePageAssociation()`（便捷关大页关联），生成代码在 `findAll(Pageable)` 末尾调 `consumePending()` 自动清除 → **只影响最近一次分页查询、无需手动 clear**（与 PageHelper.startPage 一致；若开启后没紧跟分页查询则顺延到下一次）。
- 保留 `set`/`clear` 供请求级持久场景（如拦截器）。`wrap(Runnable/Callable)` 同步透传 CONTEXT+PENDING。
- 测试改 `disableLargePageAssociation()` 演示一键关闭 + 自动清除不泄漏到下一次查询；文档第 8 节第 5 点同步更新。

## refinement：分页关联加载升级为三态模式 AssociationMode
- 用户要求把布尔开关 `largePageAssociationEnabled` 升级为三态枚举 `AssociationMode`：
  `0 DEFAULT`（20 条分页级联：≤阈值 20 eager 加载，>阈值不自动级联，交给调用方）、
  `1 CASCADE`（强制级联，任何页大小都加载）、`2 DISABLED`（强制关闭，任何页大小都不查询）。
- 新增 `AssociationMode` 枚举（runtime 包）；`AutumnDataContext` 改为 `(AssociationMode mode, int largePageThreshold)`，
  DEFAULT 模式下阈值才生效；`defaults()` = `DEFAULT, 20`。
- `AutumnDataContextHolder` 便捷方法 `disableLargePageAssociation()` → 拆分为 `forceCascade()`（CASCADE）/
  `disableCascade()`（DISABLED）；保留 `startContext/set/clear/consumePending/wrap`。
- compiler `findAllPageableBody` 改为按 `mode()` 的 switch：`CASCADE→true` / `DISABLED→false` / `default→size<=threshold`，
  末尾仍 `consumePending()`。**关键行为变化**：默认（DEFAULT）现在 > 阈值不再级联（此前默认 largePageAssociationEnabled=true 会级联）。
- 测试改写为 5 例覆盖三态 + 一次性自动清除不泄漏；文档第 8 节第 5 点同步更新为三态描述。
- 验证：`./mvnw -o clean test` 全模块 BUILD SUCCESS（using 16 例 GeneratedUserRepositoryImplTest 全绿）。

## 新特性：分页 + 排序（Page<T> + 末位 Pageable）
- 动机：此前 `findAll(Pageable)` 只按主键排序，`OrderBy` 又不能带 Pageable，二者无法组合。
- 实现：返回 `Page<T>` 且末位形参是 `Pageable` 的派生查询 → `Kind.PAGE`。
  - `DerivedQuery` 增加 `countSql` 组件与 `Kind.PAGE`（保留 10 参便利构造兼容旧调用）。
  - `DerivedQueryParser.parse(...)` 增加 paged 重载：`bind` 只吃去掉末位 Pageable 的形参表；
    `First/Top` 与 Pageable 互斥（编译期报错）；主语句带编译期 ORDER BY，另生成同 WHERE 不带 ORDER BY 的
    `SELECT COUNT(*)`。
  - `AutoRepositoryProcessor` 识别 Page 返回 + 末位 Pageable，并校验返回类型必须是 `Page<Entity>`。
  - `ImplementationSource` 为 PAGE 额外生成 `SQL_XXX_COUNT` 常量，方法体调 `autumn.page(...)` 并按
    AssociationMode 三态门控关联装配。注意参数顺序：`page(select, count, ROW_MAPPER, pageable, args...)`。
  - `AutumnJdbc` 新增 `page(sql, countSql, mapper, pageable, args...)` 重载。
- 排序字段仍由方法名 OrderBy 编译期映射 → 组合分页排序依然无运行期拼串，符合框架「编译期决定一切」原则。
