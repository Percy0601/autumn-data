# 2026-11-02

## 收尾 A/B/C：@Query、@ManyToOne、多层关联路径、标识符引号

接续 11-01 的 A（关键词收口）与 B（Distinct / First-Top / deleteBy），本轮把 C 档做完并全部跑绿。

### C1 已完成：@Query 自定义 SQL
- 新增注解 `xyz.wewin.autumn.data.jdbc.annotation.Query`（`@Retention(CLASS)`，`String value()`）。
- `DerivedQueryParser.custom(...)` 绕过方法名解析，按返回类型定 Kind（List/Optional/void/long），参数顺序绑定。
- `ImplementationSource`：`custom` 跳过关联装配；`void` 返回不加 `return`。
- 踩坑：`AutoRepositoryProcessor.queryAnnotationValue` 用了 `AnnotationMirror` 却没 import（补 `AnnotationMirror`/`AnnotationValue`）；
  `sourceName` 的 `switch` 缺 `case VOID`，`void` 方法被读成 `java.lang.Object` 导致 @Query 判型失败 —— 已补 `case VOID -> "void"`。

### C2 已完成：@ManyToOne 加载 + 多层关联路径
- `EntityMetadata.Association` 扩到 10 参，新增 `toOne` / `foreignKeyGetter`；
  `statementKey()` 按形态给 `…ByIds`（多对一）/ `…ByParentIds`（一对多）。
- `EntityIntrospector`：dispatch 改为按注解分派；新增 `manyToOne(...)`、`introspectChild(...)`（visiting 集合防环），
  `MAX_ASSOCIATION_DEPTH = 2` 让子实体也收集关联以支持多层路径。
  关键让步：外键标量字段只在 `depth == 0` 强求 —— 否则 `Order.owner` 这类回指会误报错（两个既有测试因此先红过）。
- `CrudSqlGenerator.childByIdStatement`：多对一按子表主键 `IN` 取子实体。
- `ImplementationSource`：`childRowMapperFieldToOne` + `attachToOneMethod`（父外键 → 子主键索引 → 挂回单值字段）。
- `DerivedQueryParser`：`resolveProperty` → `resolvePath` 递归下钻；`Resolved` 改为持 `List<Association> path`，
  `wrap` 从内向外包嵌套 `EXISTS`；连接方向按 `toOne` 分（`child.id = parent.fk` vs `child.fk = parent.id`）。

### C3 已完成：标识符引号（默认关闭）
- 做法：不逐处改 SQL 拼装，而是 `EntityMetadata.quoted(meta, dialect)` 造一份「引号视图」喂给
  `CrudSqlGenerator` 与 `DerivedQueryParser`；`ImplementationSource` 仍用原元数据（结果集标签不受引号影响）。
- 编译期选项 `-Aautumn.data.jdbc.dialect=mysql|postgresql|h2|default` 开启，默认返回 null = 不加引号，保既有 H2 测试绿。
- 顺手在测试里加了 `compile(dir, sources, options)` 重载以传 `-A…` 选项。
