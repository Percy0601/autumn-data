## autumn-data-jdbc 代码评审 + 定位分析（用户请求）

通读全量源码后给出定位判断。核心事实（已核实）：

- 编译期 APT（`AutoRepositoryProcessor`，JSR-269）为 `@AutumnRepository` 接口生成 `<Repo>Impl.java` + SQL `.properties`，运行时零反射、无代理。
- 标准 `CrudRepository` 全量方法 + `PagingRepository#findAll(Pageable)` + 一对多（两语句按外键分组，规避 N+1）+ 批量写（insert/update 分拨、生成键顺序回填、分块提交）+ 事务参与（经 Spring DataSourceUtils，@Transactional 自动生效）。
- 严格依赖分层：核心 `autumn-data-jdbc` 零 Spring 运行期依赖（仅 HikariCP + slf4j + jakarta.persistence-api 编译期）；Spring 只在 starter。SQL 与实现分离为 .properties，用 JDK Properties 加载。
- 端到端测试已验证：编译器进程内 javac 测试、直连 H2 验证生成类、SpringBootTest 事务测试。

### 我的判断（诚实版）
- 范式不新：编译期 CRUD 生成是 Micronaut Data / Doma2 / jOOQ 已走的路，非"世界首创"。
- 但**组合与工程取舍高级**：Spring Data 接口写法 + Micronaut 式编译期零反射生成，瞄准 Spring Data 运行时代理/反射开销与原生镜像不友好；核心零 Spring 是可嵌入非 Spring 场景的刻意设计；天然 GraalVM Native/AOT 友好。
- 真正对标上 Micronaut 的缺口：**派生查询（`findByNameAndAge`）尚未实现**（docs/spring-data-derived-query.md 已写详尽规范，是现成蓝图）；record 实体、多对多装配、@Query 自定义 SQL 仍在路上。当前能力=标准 CRUD + 一对多，未到 Micronaut 量级。

### 已发现的真实改进点（后续可出力）
1. `CrudSqlGenerator` 生成的 SQL 用裸标识符，未走 `Dialect.quoteIdentifier()`（接口已有但没接）——`order`/`user` 等保留字列名/表名会崩，属健壮性+正确性隐患。
2. 派生查询解析器（PartTree 等价物）是最大工程增量。
3. record 实体支持（canonical constructor 替代无参+setter）、多对一/多对多装配生成、Oracle/SQL Server 方言。

## 方案 B 落地：完全去 Spring，MyBatis 式事务分层（用户拍板 "方案B 就行"）

目标：核心模块零 Spring 运行期依赖、可脱离 Spring 使用；starter 仅作 Spring 适配。

### 核心层（autumn-data-jdbc，新增/迁移，零 Spring）
- `runtime/ConnectionSource`：连接+事务抽象（对标 MyBatis `Transaction`）。
- `runtime/JdbcConnectionSource`：原生 JDBC 自管连接/autocommit/提交/回滚；`Autumn` 无 Spring 引导用（对标 SqlSessionFactory）。
- `runtime/AutumnJdbc`：从 starter 的 `spring/AutumnJdbc`（基于 spring-jdbc `JdbcClient`）迁移，改为只用 `java.sql` 重写；构造器 `(ConnectionSource, Dialect, FetchPolicy)`；含 `SqlException`、静态 `partition`。
- `runtime/RowMapper<T>`：核心自有，签名对齐 spring-jdbc，零依赖。
- `runtime/Autumn`：`using(DataSource)` / `create(Repo.class, dataSource)` 无 Spring 引导。

### 编译器（autumn-data-jdbc-compiler）
- `ImplementationSource`：`AUTUMN_JDBC`/`ROW_MAPPER` 常量改指 `runtime` 包；**删除生成类上的 `@org.springframework.stereotype.Service`**。
- `AutoRepositoryProcessor`：收集处理到的仓储接口 FQN，写 `META-INF/autumn-data/repositories`（供 starter 注册）。

### Starter 适配层（autumn-data-jdbc-spring-boot-starter）
- 删除旧 `spring/AutumnJdbc.java`（被核心版取代）。
- `spring/SpringConnectionSource`：`ConnectionSource` 实现，委托 `DataSourceUtils`，自动加入 `@Transactional`；`@DisposableBean.destroy()` 还连接。**关键坑**：`getConnection()` 在 Spring 事务中必须每次经 `DataSourceUtils` 取事务绑定连接，绝不能复用上一条（已回滚）事务遗留的缓存连接——否则生成写操作脱离当前事务（实测导致 TransactionParticipationTest/StarterUsingIntegrationTest 失败）。
- `spring/RepositoryRegistrar`（`BeanDefinitionRegistryPostProcessor`）：读 `META-INF/autumn-data/repositories` 把 `<Repo>Impl` 注册为 Spring Bean，构造器自动装配核心 `AutumnJdbc`。
- `AutumnDataJdbcAutoConfiguration`：只依赖 `spring-boot-starter-jdbc`；提供 `Dialect`/`FetchPolicy`/`ConnectionSource`/`AutumnJdbc`/`RepositoryRegistrar`；`@AutoConfiguration(after=DataSourceAutoConfiguration)`。
